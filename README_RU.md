## Что доказано

Рассмотрим произвольное множество точек на евклидовой плоскости с цветами $0,1,2,3$, расположенными по циклу. Для любых двух различных точек минимальное расстояние равно:

| Отношение цветов | Минимальное расстояние |
| --- | --- |
| Одинаковые | $\sqrt 2$ |
| Соседние в цикле $0,1,2,3,0$ | $\sqrt 5/2$ |
| Противоположные в этом цикле | $1$ |

При этих условиях число точек в любом ограниченном круге конечно, а верхний предел отношения числа точек в круге радиуса $R$ к его площади при $R\to\infty$ не превосходит 1. Периодичность множества и существование обычного предела плотности не предполагаются.

Статья также показывает достижимость оценки и выводит пятимерное следствие для определённого семейства упаковок из четырёх сдвигов $D_3$ над плоской базой. Глобальная оптимальность $D_5$ среди всех пятимерных упаковок здесь не утверждается.

## Как запустить Lean

В терминале из корневой папки репозитория выполните:

```bash
bash verify.sh
```

Поддерживаются macOS и GNU/Linux; в Windows используется WSL. Нужны Bash, Git, curl, tar, утилита SHA-256 и интернет для первой установки. Команда сама получает закреплённые версии Lean и зависимостей. Первая проверка может занять десятки минут и потребовать значительных загрузок.

Скрипт проверяет контрольные суммы исходников и версии зависимостей, собирает все 51 проектный модуль и проверяет конечные теоремы. Признак успешного завершения:

```text
SUCCESS: all project proof modules compiled and the final axiom guards passed.
```

Результат сохраняется также в `lean/build-logs/SUCCESS.txt`, формулировки и список аксиом — в `lean/build-logs/final-verification.log`. Не запускайте `lake update`: для воспроизведения нужны версии из комплекта.

Используются Lean **4.28.0** и Mathlib commit `8f9d9cff6bd728b17a24e163c9402775d9e6a365`. Подготовлен [GitHub Actions workflow](.github/workflows/lean.yml), который выполнит ту же проверку после загрузки репозитория. Его выполнение на GitHub пока не проверено.

## Что означает успешная проверка

Lean доказывает верхнюю оценку 4.1 в полной общности, включая переход от периодических к произвольным конфигурациям. Внешний интерфейс [`Audit41.published_statement`](lean/Audit41.lean) использует исходные расстояния и раскраску, заданную только на самом множестве точек. Локальная конечность выводится из условий.

Все три конечные теоремы используют только `propext`, `Classical.choice` и `Quot.sound`. Дополнительная аксиома или пропущенное доказательство в их зависимостях приводит к провалу проверки.

**Не формализованы:** пример достижения плотности 1, классификация локального равенства, конкретные коэффициенты конечной оценки из статьи, пятимерный перенос плотности и отождествление с $D_5$. Они доказаны в тексте статьи. Lean не проверяет авторство, библиографию или приоритет.

Полная компиляция всех модулей выполнена **23 сентября 2026 года**. **24 сентября** те же исходники повторно проверены с использованием уже собранных модулей; конечный файл проверки обработан заново. Сборка и проверки завершились успешно. [Отчёт и журналы](verification/README.md) различают эти два запуска.
